## 如何使用互動時間軸

1. 第一頁選擇右側／左側／雙側評估並上傳**必填側面影片**。正面影片依然選填。
2. 在第一頁展開 **「🎬 影片時間軸｜拖曳區間設定負重與肌肉使用」**。
3. 影片畫面可直接播放（支援的 MP4、24 MiB 以下）。下方的多張縮圖能快速找到搬運位置；**影片過大、MOV／AVI 或瀏覽器不支援的格式**，則使用 Streamlit 原生播放器配合縮圖選取，功能不會被取消。
4. 按 **「＋ 新增區間（兩個端點）」**，時間軸會顯示彩色區間，左右各有一個白色拖曳把手：**左邊調起點、右邊調終點，中間拖動整段**。也可按 **「✚ 點兩下選起點與終點」**，先在縮圖選開始，再選結束，快速建立一段。
5. **可以反覆新增多段**，不必預先輸入區間數。每段可分別填寫名稱、肌肉使用 0／1、負重／施力 0～3；最多 24 段以免介面與報表過度複雜。可刪除已選區間。
6. 所有區間確認完成後，按 **「✓ 儲存全部區間並套用」**；只有此動作會把設定送回 Python。若區間時間重疊，會擋下儲存並指出原因。
7. 沒有覆蓋的秒數使用第一頁原本的預設分數。後續正常按下一步完成鏡頭同步與 RULA 分析；有少數例外照片時仍可使用原本的「照片批次修改」。

**雙側同步時間基準：** 左右都有上傳時，以**右側原始影片的播放秒數**當作時段選取基準。左側會依已確認的雙鏡頭同步結果對應，不需要設定兩遍；只分析左側時以左側影片為準。

**重要的 RULA 評分原則：** 肌肉使用 +1 要依持續維持姿勢或重複頻率等實際作業條件判定，不是畫面中正在抱箱子就必須加 1。負重／施力分數需依真實重量和施力方式決定。此時間軸只幫使用者將已知作業條件正確套用到對應的樣本照片，並**不會自動辨識真實重量**。

## 安全及穩定性

- 使用 `streamlit.components.v1.declare_component` 與純 HTML/JavaScript，雙向傳遞使用者的區間。沒有第三方 CDN 或 JavaScript 套件依賴。
- 嵌入播放影片採 session 內的 base64 原始上傳資料；**不把使用者影片寫到可被其他人存取的靜態資料夾**。
- 24 MiB 以上或瀏覽器不適合內嵌的影片會改用 Streamlit 播放器；縮圖與雙端點時間軸照常運作。
- Python 收到區間後會再驗證：數量、起訖、長度、分數、時間重疊、是否超出影片長度。不合法的設定不會覆蓋上一份已儲存結果。
- 更換左右側影片時會清掉舊影片時段，避免把上一支影片的秒數誤套到另一支。
- 原本整段影片與多段作業條件的分數優先順序不變：**照片批次覆寫 > 時段設定 > 第一頁預設**。分析後仍能從 CSV／ZIP 查詢套用的作業條件來源。

## 首次部署快速驗收

1. 上傳搬運影片，影片播放器能播放或有上方備援播放器，縮圖正常。
2. 建立 4～9 秒「拿取」（例如負重 1 分）和 9～14 秒「搬運」（例如負重 2 分），左右拖曳並按儲存。
3. 返回此步仍可見兩個保存區間；不允許時段重疊。更換影片後不應保留舊時段。
4. 啟動分析，檢查報表中不同秒數的負重與肌肉分數，以及對應的 `作業條件設定來源` 欄位。
5. 用一張照片進行人工批次負重修正，確認只修改那張、不修改其餘照片；下載 ZIP 確認報表內容仍完整。
