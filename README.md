# RULA 計分正確性修正版（2026-10-30）

**版本：`RULA_VERIFIED_TABLES_FRONT_REVIEW_2026-10-30`**  
**適用：** 正面選填、右側單鏡頭、左側單鏡頭、左右同步鏡頭；保留原本 Hand 2D 優先、照片批次修正、可播放影片與雙端點拖曳時間軸。

> **重要：這是經離線邏輯測試的修正版，不是經人工標準驗證的零誤差系統。** 原始 `2221.zip` 無 MP4，只含擷取影格與保存的數據。因此附上的「歷史資料回算」是離線重新查表，**不是**實際重新跑過 MediaPipe 的影片分析。要取得新版正式影像與分數，務必在 Streamlit Cloud 上重新上傳**原始 MP4/MOV** 分析。

## 本次具體修正

1. **RULA Table A / B / C 正式查表：** 以既定參考的 RULA 工作表（使用者提供的蕭世平 2016 論文，表 3-8、3-9、3-10）建立固定值；Table A 144 格、B 72 格、C 81 格逐格對照，不以舊版程式自算值當標準。C 表的輸入範圍也改為完整的 1～9。
2. **頸部側彎：** 停用前一版正面頭肩投影角度「直接自動 +1」；保留在技術診斷，正式計分採使用者**分析前一次設定**，只有例外姿勢才用照片批次修改。原因是既有 9 張自動陽性照片，經使用者查看正面影片均未觀察到明顯側彎；並不代表已能自動辨識真正的側彎。
3. **共同頸部分數：** 左右共同採用分數（包括「不影響 AL、無須人工確認」與「人工確認」兩種情境），都必須重新帶入兩側 RULA Table B/D/C 查表。ZIP 內的最終逐側結果、部位明細與人工比對空表，使用同一份最後採用的頸分與總分。
4. **正面補正品質門檻：** 上臂外展、前臂跨中線、前臂向外側、軀幹側彎只有正面關鍵點和粗略視角品質通過，才使用影像估測；若正面旋轉、肩寬投影縮短、肩線傾斜、缺點或讀取失敗，使用分析前的作業設定，**不得自動宣稱「沒有加分」或「高信心準確」**。輸出會保存來源及品質註記；這些門檻尚未通過實拍人工準確率驗證。
5. **防止誤剔除：** 正面影格暫時無法讀取，不會使正常的側面影格自動遭剔除；單純缺少正面也不會把每張照片一律列為「需人工複核」。骨架本身真正有異常的樣本仍照正常品質複核流程處理。
6. **時段與人工負荷設定保持原樣：** 保留拖曳時間軸，使用者設定肌肉使用／負荷的時間段，抽樣依影片秒數帶入；例外照片可以多選批次修正，沒有新的強制逐張勾選頁面。
7. **報表保留來源：** ZIP 加入 `技術診斷/程式與計分版本.json`，標註查表依據、頸側彎模式、正面補正限制。照片上原有的標示是分析當下數值，後續人工修改請以 **「複核後結果」的 CSV** 為準。

## 使用者實際操作

1. 上傳需要的側面影片，正面影片選填；確認鏡頭同步。
2. 如果有搬運負荷／肌肉使用階段，使用原有的可拖曳影片時間軸設定；RULA 肌肉使用加分依作業重複頻率和靜態持續時間，不是看到箱子就 +1。
3. 在分析前確認一次作業共用條件（包含頸部側彎的「有／沒有」），這是**使用者提供的作業資訊**，不是 AI 已辨識正確。
4. 分析完成直接看 RULA 評分；只有某些照片有特殊扭轉、失衡或負荷變化才使用照片批次修改。
5. 下載 CSV/ZIP：正式使用 `複核後結果/`，保留 `原始分析/` 供分析與人工比對；**正式研究不能把人工修正後的分數說成純自動準確率**。
