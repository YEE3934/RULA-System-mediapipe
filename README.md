# RULA 智慧姿勢評估系統｜結案前批次補正與人工驗證版

**部署識別：`RULA_FINAL_BATCH_REVIEW_2026-10-29`**

這份是完整 Streamlit `222.py`，從「正面鏡頭選填版」延伸，**不需要搭配其他版本的 222.py**。保留雙側共用頸部分數、必要時的頸部局部人工確認、Hand 2D 優先（Pose 2D 備援）、骨架品質檢查、影片同步、照片與 ZIP 匯出。

## 使用者最重要的流程

1. 在「影片與基本設定」選 **右手側／左手側／左右側同步**。右側必上傳右側、左側必上傳左側、正面影片選填。抽樣數可設 30。
2. 確認所需影片的同步。單一側面影片不需要跨鏡頭同步；兩支以上要檢查同一動作事件。
3. 分析前人工條件／負重／肌肉使用是**整段初始候選設定，不代表所有照片都符合**。沒有正面鏡頭，也可以先進行角度分析。
4. 按「啟動分析」後進入結果分頁；先打開 **「✅ 照片批次補正」**。可打開全體骨架縮圖、選定一側，按「全選這一側的有效照片」，檢查條件後一次確認。
5. 例如第 7～12 張有軀幹扭轉，選取這六張，把「軀幹扭轉」選成「有」，按 **套用補正並確認**。如果第 10 張是例外，再單獨選第 10 張調整。
6. **負重與肌肉使用**可以依作業階段批次修改。空手返回不要沿用搬運階段的負重。腿足、腕扭轉、上臂支撐等也可批次修改。
7. 對沒有足夠依據的條件選「無法判斷」，**該照片只保留候選分數，不會進入可信統計**。現場觀察或其他照片可提供判斷依據，不要為了讓流程通過而隨便選「沒有」。
8. 批次完成後，先查看風險總覽，再到「角度檢視→頸部」確認確實會影響行動等級的左右分級衝突，必要時到「異常／人工覆核」做完整人工改分或剔除。
9. 到「下載」取得 ZIP；ZIP 中有 **`研究驗證/人工評分比對空表.csv`**，方便你們做人工角度及 RULA 評分驗證。

> **非常重要：** 骨架照片上印的 Grand Score 是分析開始時的**舊候選分數**，不是批次補正更新後的分數；請以 **「複核後結果」與結果頁風險統計**為準。

## 新版補正原則

| 條件 | 判定依據／用法 |
|---|---|
| 上臂、前臂、手腕、頸部與軀幹基本角度 | 系統逐張自動分析；影像估計值不是人體三維角度真值 |
| 上臂外展、前臂跨中線／向外、軀幹與頸部側彎 | 有正面畫面可使用影像候選；無正面須利用現場觀察、其他可見畫面或批次人工確認 |
| 聳肩、軀幹／頸部扭轉、手腕尺橈偏、手臂支撐、腿足支撐等 | 依符合條件的照片／動作階段批次確認，例外照片個別覆蓋 |
| 肌肉使用 +1 | 依整體作業重複頻率及靜態維持判斷，不能只根據單張圖片猜測 |
| 負重／施力 0～3 | 依實際負重、施力型態、作業階段判斷，不把持物負重套到所有空手照片 |
| 雙側共用頸部分數 | 兩側均完成補正後，重新以完整 RULA 查表評估左右候選分級是否改變 AL；必要時只確認頸部 |

**先確認整批／再修改例外，不等於 AI 自動判斷那些人工條件。** 對外描述應為「自動角度分析＋批次人工補正的半自動 RULA 評估」。

## ZIP 內容說明

- `原始分析/`：執行初始分析後、尚未進行照片級確認的候選結果（原有原始報表不覆寫）。
- `複核後結果/逐側結果.csv`：補正、骨架品質、頸部分級和完整人工改分之後的結果；未確認者總分留空。
- `複核後結果/雙側結果.csv`：只有雙側模式才提供完整雙側評級。若一側無有效評分，不冒充完整雙側最高分。
- `複核後結果/單側結果.csv`：單側模式。
- `複核後結果/逐張人工補正確認.csv`：各張使用的條件、確認狀態與人工改動欄位。
- `複核後結果/照片補正後部位評分.csv`：各張重算後的各部位分數，便於查核。
- `研究驗證/人工評分比對空表.csv`：包含初始候選與複核後 RULA；人工角度、人工 RULA、評分者編號等欄位**預設空白**，請人工獨立填寫。
- `技術診斷/`：關鍵點、品質和頸部新舊測量方式等資訊；原始照片、骨架圖片及同步設定也保留。

## 正式驗證時的必要區分

**初始候選分數不等於完全純 AI：** 分析前仍可能輸入腿足支撐、前臂旋轉、負重、肌肉使用及部分姿勢補正。

建議研究報告分成：(A) 系統初始候選結果與人工評分的一致性（如實註明分析前人工輸入條件）；(B) 批次補正與品質複核後的人機協作結果；(C) 關節 2D 代理角度與獨立人工量角的誤差。**不能用人工修正後的分數宣稱全自動準確率。** 頸部 2D 幾何角不能直接當作人體頸椎角度真值。

## 部署

1. ZIP 解壓縮後，將 `222.py`、`requirements.txt`、`packages.txt` 和 `scripts/`、`models/` 放到 GitHub 專案根目錄；原本已有 `models/hand_landmarker.task` 時請保留。
2. Streamlit Cloud 主程式設為 `222.py`、Python 3.11。`requirements.txt` 沿用原本可運行的套件組合。
3. 更新後在側欄「系統維護資訊」檢查部署識別 `RULA_FINAL_BATCH_REVIEW_2026-10-29`。
4. 在現場五組正式影片前，先用其中一段**少量 5～10 張**測試：右側／左側／雙側、正面有／無、批次修改 1 張扭轉與數張負重、確認前後分數、下載 ZIP 核查 CSV。

## 測試狀態與限制

已進行 `python -m py_compile 222.py`、原有離線回歸測試及新增批次補正驗證，涵蓋各種鏡頭組合、不同 FPS 合成影片讀取、雙側共用頸部分數、單側編輯與未知欄位、原始候選不覆寫、雙側完整樣本限制、ZIP 及人工比對表。

**目前執行環境沒有 Streamlit 與 MediaPipe，因此不能聲稱已在 Streamlit Cloud 透過真實工廠影片完成端到端運行。** 正式資料收集前仍需使用至少一段真實影片完成線上驗收。RULA 標準查表與人工角度參考法應使用同一版標準工作表獨立核對；品質篩檢也不能保證每一張角度都正確。
