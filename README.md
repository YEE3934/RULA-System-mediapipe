# RULA 側面有向角度＋預設直接評分版（2026-10-30）

部署版本：`RULA_DIRECTIONAL_DEFAULTS_2026-10-30`。以先前「正面選填、雙側共同頸部分數、照片批次補正」版本為基礎修改，保留原有分析與報表功能。

## 這次修改的重點

1. **取消「每張照片都要確認才能查看評分」**。分析後立即依原本分析前選項＋可用的逐張影像辨識結果，顯示「候選 RULA 分數」。不再出現幾十張未確認就讓總覽歸零的情況。僅被標示為「無法確認」的補正、品質必要複核、或可能改變雙側 AL 的頸部衝突，仍暫緩採信。
2. **照片批次補正完全選用**。有需要時才多選照片、批次改負荷／扭轉／支撐／偏移等。只重跑 RULA 查表，不重跑 Pose / Hand；未修改的照片沿用原始預設。單張例外仍能處理。
3. **上臂向後伸展**在「自動辨識設定」改為預設勾選、移除「實驗性」字樣。另新增預設勾選的**軀幹向後伸展**與**頸部後仰（保守候選）**。這三項使用同一套側面「有向角度」，先判斷人物朝向，再以軀幹和上臂向量區分前傾、後傾。朝向不明、關鍵點不足或接近判定邊界時，**回到分析前使用者輸入的設定**；不把零或負度數直接當成姿勢真值。
4. **一般報表和 ZIP 會區分來源**：「分析前預設／影像候選」、「批次／單張人工確認」及「無法確認」；內部比較欄名保留相容性，但 UI 與報表明示這是**候選統計**，不是人工已驗證的準確率。
5. 原先**正面選填**、左右鏡頭同步、Hand 2D 優先／Pose 2D 備援、RULA 查表、品質異常審核、共同頸部評分／必要時人工確認、剔除照片和研究驗證 CSV 保留。

## 重要限制

- **有向角度是攝影機畫面的 2D 估測，不是經校準的 3D 人體關節角度。** 需鏡頭大致水平、人體偏側面、面向可見；人體扭轉、嚴重彎腰及臉部被遮住時可能無法正確判斷。系統有信心門檻與模糊區，但門檻**尚未以人工角度或動作捕捉黃金標準驗證**。
- **頸部後仰特別不可靠**：使用耳／眼與軀幹的 2D 投影只判斷明顯候選動作，接近臨界時維持人工設定。不可宣稱它量到實際頸椎後伸度數；有疑義應確認 RULA 頸部基礎等級。
- **並非全部 RULA 補正可用畫面安全自動化**：手腕旋前旋後、手腕尺橈偏、上臂支撐、聳肩、軀幹扭轉、腿足平衡、肌肉使用與外部負荷等，仍需現場資訊或人工觀察。缺正面影片時，跨中線、外展與側彎先採使用者分析前的預設，必要時補正。
- 如果「空手準備→拿物→搬運→放下」負荷不同，使用者應在照片批次補正中只修正適用照片，不可把某一施力階段的設定誤當整段都成立。
- 先驗證原始候選分數，再比較人工補正後結果；**不要混用「人機協作後分數」宣稱純 AI 準確率**。每張照片也可能有品質警示或頸部必要複核，這類狀態仍可能使正式候選彙整留空。

## 部署

使用 Python 3.11。將此資料夾的 `222.py`、`requirements.txt`、`packages.txt`、`scripts/`、`models/` 上傳／覆蓋到原本 GitHub Streamlit 專案；Streamlit Cloud 主程式維持 `222.py`。Hand 模型若未預先放入，沿用原有下載腳本。

## 操作建議（你們的 240 張人工驗證）

1. 選右側、左側或左右雙側；**正面影片選填**，左右同步影片仍需對齊。
2. 在「自動辨識設定」保留前／後伸展自動選項；在下一頁輸入真實作業的腿足支撐、手腕扭轉、肌肉使用和負荷等初始設定。
3. 分析完直接看「風險總覽」與「下載」；不必全選確認每張照片。
4. 只有某幾張姿勢與初始設定不同，才用「照片批次補正」多選修改；不知道的條件可標「無法判斷」。
5. ZIP 中「原始分析」保存原本分析候選，「複核後結果」保存後續修改、來源與狀態，「研究驗證/人工評分比對空表.csv」供你們做人工比較。
